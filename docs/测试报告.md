### 本轮开发期发现并修复的缺陷

1. **发证必 500**:`biz_certificate.cert_no` 建表为 NOT NULL,而实现采用"先插入再回填自增编号",首插必违反非空约束 → 改列可空(唯一键允许多 NULL),插入后回填;
2. **Jackson 双大写字母陷阱**:`Question.qType` 经 Lombok 生成 `getQType()`,Jackson 将其推导为 `qtype`,导致入参 `qType` 绑不上(全部建题 400"无效的题型")、出参键名也错 → 实体加 `@JsonProperty("qType")` 显式指定;
3. **升级脚本字符集坑**:mysql 客户端未加 `--default-character-set=utf8mb4` 导致菜单中文乱码 → 已修复数据并在脚本头部加提醒。

## 三、上轮结论(2026-11-13)

### A. 学时重算:软删与唯一键冲突(高危,补签/结班必 500)

- **现象**:课节结束后补签,或结班触发第二次 `recomputeClassHours` 时,接口 500,`Duplicate entry 'xx-xx' for key 'biz_hour_record.uk_hour_schedule_user'`。
- **根因**:`HourRecord` 继承 `BaseEntity` 的 `@TableLogic`;MyBatis-Plus 的 `delete()` 实际执行 `UPDATE del_flag=1`。唯一键 `uk_hour_schedule_user(schedule_id, user_id)` 不区分软删行,第二次重算先软删再插入同键新行必然冲突。
- **修复**:`HourRecordMapper.deleteSignRecords()` 物理删除 `source=1` 的签到派生学时(可由考勤完整重建);`recomputeClassHours` 改用该方法。
- **同型排查**:`removeStudent` 已是物理删除(`deletePhysical`),无同类问题。

### B. 班次状态机:筹备中不能直接开始(内派班走不通)

- **现象**:批量添加学员后直接 `PUT /biz/classes/{id}/status?status=2` 返回 400"班次当前状态不允许该操作",必须先发布报名。
- **修复**:`changeStatus` 允许 `0(筹备) → 2(进行中)`,覆盖内派/指令性培训跳过公开报名的场景;`0→1→2` 原路径不变。

### C. 评估汇总均分口径错误

- **现象**:四项全 3 分,`overallAvg` 返回 12.0(总分)而非 3.0(均分)。
- **根因**:`totalScore` 存的是评分项求和;`summary()` 又对 `totalScore` 求和后除以作答人数,等价于"人均总分"。
- **修复**:`overallAvg` 改为全部评分项取值的算术平均(与逐项均分同口径);`totalScore` 仍存单份作答总分。

### D. 需求审核参数名不一致

- **现象**:deep 用例传 `{"pass":true}`(与计划/课程/学时审核一致)被当作"驳回"。
- **修复**:`NeedController.audit` 同时接受 `adopt` 与 `pass`;前端继续用 `adopt`(与 e2e 一致)。

### E. 学时台账 keyword 不搜备注

- 手工补录常用备注定位记录;`selectPageVo` keyword 追加 `r.remark LIKE`。

### F. 上一压缩点已完成、本轮回归验证的修复(9 个 Java 文件)

1. `AuthInterceptor`:每请求 `selectById` 校验用户存在且 `status=0`,停用/删除后旧 token 立即 401;
2. `ClassMapper.lockById`:`SELECT ... FOR UPDATE` 行锁,并发报名/签到入班防超卖;
3. `ClassService`:日期倒挂校验、编辑容量不得小于现有学员、结班自动结束课节+重算+标缺勤、补签(含已结束课节)后立即重算、重算仅回退 `status=2→0`;
4. `PlanService.save`:startDate after endDate → 400;
5. `CourseService`:编辑强制沿用原 `sourceType/sourceId/externalCode`;
6. `EvalService.fill`:班次评估仅允许 `evalLevel=1` 模板;
7. `UserService`:删除前校验学时/学员/需求关联,`changeStatus` 枚举校验,内置 admin 不可停用;
8. `NeedService`:重复关闭征集 400,删除有申报的征集 400;
9. `IntegrationService`:数据源状态枚举校验,忽略不存在暂存课 400。

## 七、历史轮次(2026-10-31)发现并修复的问题

### 安全类
1. **横向越权**:提交/删除需求未校验属主 → 补属主校验(管理员放行);
2. **明文密码落审计日志** → `@OperLog` 切面脱敏 `password/oldPassword/newPassword`;
3. **登录无爆破防护** → 同账号 5 次失败锁定 10 分钟;
4. **500 响应泄漏内部异常细节** → 对外固定文案,详情仅写服务端日志;
5. **JWT 密钥/数据库口令硬编码** → 环境变量注入(`TRAIN_JWT_SECRET`、`TRAIN_DB_PASSWORD/HOST/USER`);
6. **课程删除未检查课表引用** → 已引用课程禁止删除。

### 业务规则类
7. 签到自动入班无容量校验 → 补容量校验;
8. 已结束/已取消班次仍可改课表、结课、重算学时 → 课节写操作校验父班次状态;
9. 课节结束后仍可补签 → 本轮已按新口径放开"班次进行中的补签"并即时重算;
10. 学时来源可伪造为"签到自动" → 手工入口收敛为 2 补录 / 3 外部认定;
11. 评估必填项仅前端约束 → 服务端强制必填;已有作答的模板条目冻结;
12. 更新用户不传 roleIds 会清空角色 → 仅显式传入才重新分配;
13. 重置密码可重置内置管理员 → 拦截 id=1。

### 健壮性
14. 并发竞态:考勤/学员/学时唯一索引 + 冲突改更新;
15. 分页无上限 → `PageQuery.of()` 钳制(页码≥1、单页≤200);
16. 结班未参训学员自动标缺勤;
17. 评估模板 `items` 兼容 JSON 字符串与原生数组。

### 确认干净项
- SQL 注入:全部 `#{}` 预编译,无 `${}` 拼接;
- 管理接口 `@RequirePerm` 全覆盖,拦截器仅放行 `/auth/login` 与 `/error`;
- 前端无 v-html,Vue 默认转义;
- 学时/评估"我的"接口按登录人过滤;员工访问管理接口 403。

### 遗留与建议(不阻塞交付)
