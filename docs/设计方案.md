# 国企培训管理系统 · 设计方案

## 1. 设计背景与原则

国有企业培训管理具有以下典型要求,系统设计据此展开:

1. **闭环管理**:培训工作必须形成"计划—实施—检查—改进"的完整闭环,避免"只办班、不评估、不改进";
2. **学时刚性约束**:干部与员工的年度培训学时是硬指标,需要精确到人的台账与达标预警;
3. **分级授权与审批**:需求、计划、课程等环节需经审核/审批后生效,权限清晰、留痕完整;
4. **审计合规**:操作可追溯,满足巡视巡察与内控审计对信息系统留痕的要求;
5. **全员参与**:员工可自助申报需求、报名、评估、查询学时,提升参与度与数据真实性。

## 2. 行业对标(优秀实践引入)

| 对标依据 | 在系统中的落地 |
| --- | --- |
| **ISO 10015:2019《质量管理—培训指南》** 培训四阶段(确定需求→设计策划→提供培训→评价结果) | 模块编排严格对应四阶段:需求征集/申报 → 计划审批 + 课程/师资准备 → 班次实施 + 签到 → 学时/评估统计反哺下一年度需求 |
| **《干部教育培训工作条例》(2023年修订)** 关于干部每年参加教育培训学时的要求 | 内置年度学时要求参数:管理干部 110 学时、专业技术人员/一般员工 90 学时(可在参数设置中按企业制度调整),并按人员类型自动统计达标率 |
| **柯氏四级评估模型(Kirkpatrick)** | 评估模板按"一级反应层/二级学习层/三级行为层/四级结果层"分级建设,内置一级(反应层)通用问卷与三级(行为层)问卷样例,支持自定义条目 |
| **PDCA 循环** | 计划完成率、覆盖率、人均学时、评估均分等指标构成检查(C)环节,统计结果与需求申报形成改进(A)环节 |
| **国企审计留痕要求** | 全部写操作经 `@OperLog` 切面记录操作人、IP、参数与结果,提供操作日志查询 |

## 3. 总体架构

```
┌────────────────────────────────────────────────────┐
│  前端 Vue 3 + Element Plus + ECharts (SPA)          │
│  登录/工作台/需求/计划/课程/师资/班次/学时/评估/统计/系统管理 │
└───────────────▲────────────────────────────────────┘
                │ HTTP(JSON) /api  + JWT Bearer Token
┌───────────────┴────────────────────────────────────┐
│  后端 Spring Boot 3 (8080, context-path=/api)       │
│  ┌──────────────┐                                  │
│  │ AuthInterceptor: JWT 解析 → 登录上下文          │
│  │                  @RequirePerm 权限校验           │
│  ├──────────────┤                                  │
│  │ Controller 层  │  Auth / System×6 / Biz×8        │
│  │ Service 层     │  业务规则、状态机、学时折算、汇总   │
│  │ Mapper 层      │  MyBatis-Plus + 注解SQL(分页/统计) │
│  └──────────────┘                                  │
│  切面:OperLogAspect(操作日志)  全局异常处理           │
└───────────────▲────────────────────────────────────┘
                │ JDBC
         ┌──────┴──────┐
         │  MySQL 8.0   │  sys_* 8 张 + biz_* 12 张
         └─────────────┘
```

技术选型理由:Spring Boot + MyBatis-Plus 是国企信息化最主流、运维成本最低的组合;Vue 3 + Element Plus 组件生态成熟,适合中后台快速交付;JWT 无状态认证便于横向扩展。

## 4. 功能模块设计

### 4.1 培训需求管理(对应 ISO 10015 第一阶段)

- **需求征集任务**:培训管理员按年度发起征集(标题/起止时间/说明),进行中任务全员可见;
- **需求申报**:员工填写需求标题、类别(党性教育/管理能力/岗位技能/安全合规/通用素质)、内容、理由、期望时间、建议人数,支持草稿-提交-审核状态流;
- **需求审核**:管理员采纳/驳回并填写意见;已采纳需求进入需求台账,作为计划编制输入;
- **需求分析**:按类别统计需求分布,辅助年度计划选题。

状态机:`0 草稿 → 1 待审核 → 2 已采纳 / 3 已驳回`(草稿与驳回件可编辑重报)。

### 4.2 培训计划管理

- 计划类型:年度/季度/月度/专项;主办部门、起止时间、培训对象、内容、预算(万元);
- 审批流:`0 草稿 → 1 待审批 → 2 已批准 / 3 已驳回`;批准后方可关联开班;
- 统计口径:计划完成率 = 已结班班次覆盖的计划数 / 已批准计划数。

### 4.3 培训课程管理

- 课程属性:编码、名称、五类分类、内训/外训/线上形式、标准学时、层级、培训对象、大纲、主讲讲师;
- 状态流:`0 草稿 → 1 待审核 → 2 已发布 →(下架)3`;已发布课程方可排入班次课表;
- 课程库支持关键词/分类/形式/状态检索。

### 4.4 培训师资管理

- 师资类型:内部讲师(发掘企业内训师资源)/外部专家(登记外聘机构与专家);
- 讲师等级:初级讲师/中级讲师/高级讲师/特邀专家;记录职称、专业领域、简介;
- 授课档案:自动汇聚该讲师全部课节,统计授课次数与累计授课学时;
- 约束:已有授课安排的讲师不可删除,保证历史数据完整。

### 4.5 培训班次与实施(开班)

- 班次属性:名称、类型(内训/外训/线上/混合)、主办部门、关联计划、起止日期、地点、人数上限、经费;
- 状态机:`0 筹备中 → 1 报名中 → 2 进行中 → 3 已结束`(`0/1` 可取消为 `4`);
- **学员组织**:管理员批量指定学员,或员工在"可报名"列表自主报名(校验容量与重复);
- **课表(节次)**:班次按节次安排课程(课程、讲师、日期、起止时间、本节学时、地点);
- **签到计学时**(核心):
  1. 每节次对每位学员登记签到:正常/迟到/请假/缺勤;
  2. "结束本节"时按规则折算:`正常 = 节学时`,`迟到 = 节学时 × 迟到系数(默认0.5,可配)`,`请假/缺勤 = 0`;
  3. 折算结果写入学时台账(来源=签到,状态=已认定),并汇总到学员本班累计学时;重复执行幂等可重算;
  4. 学员出勤即置"已完成"。

### 4.6 培训学时管理

- **台账唯一口径**:个人年度学时 = 台账中"已认定"记录之和;来源四种:签到自动、手工补录、外部认定、线上学习(预留);
- **认定流**:补录/外部认定记录先进入"待认定",管理员认定通过后计入统计,驳回则不计;
- **达标管理**:按人员类型配置年度要求(参数:`hour.required.manager/professional/staff`),统计页展示每人要求、累计学时、完成进度条与达标标识,支持 CSV 导出存档;
- **部门维度**:各部门学时总量、参训人数统计。

### 4.7 培训评估管理

- **模板**:按柯氏四级分级命名,条目 JSON 化存储,支持"打分项(1-5 分)"与"开放题(文本)"两类,可设置是否必填、启用/停用;
- **填写**:班次进行中或已结束时,参训学员方可填写(一人一卷,可修改覆盖);总分 = 打分项合计;
- **汇总**:逐项平均分(进度条呈现)、总体平均分、参评人数、开放题作答明细、学员总体评语时间线;评估结果用于课程与讲师改进。

### 4.8 统计分析

- 指标:班次总数/进行中、已批准计划数、计划完成率、年度学时总量、人均学时、**培训覆盖率**(本年度产生学时人数/在册人数)、待认定学时;
- 图表:月度学时趋势(折线)、部门学时(柱状)、班次状态/计划状态/需求类别/课程分类(饼图);
- 明细:员工学时达标表(含进度与达标标识)。

### 4.9 系统管理

- 用户/部门(树形)/角色/菜单(RBAC)、系统参数、操作日志;
- 内置角色:`admin`(全部)、`training_admin`(培训业务)、`employee`(自助事务)。

## 5. 数据模型(20 张表)

**系统表(8)**:`sys_dept` 部门树、`sys_user` 用户、`sys_role` 角色、`sys_menu` 菜单按钮、`sys_user_role`、`sys_role_menu`、`sys_config` 参数、`sys_oper_log` 操作日志。

**业务表(12)**:

| 表 | 说明 | 关键关系 |
| --- | --- | --- |
| `biz_need_collection` | 需求征集任务 | 1→N biz_need |
| `biz_need` | 培训需求 | user/dept/collection |
| `biz_plan` | 培训计划 | dept;被 biz_class 关联 |
| `biz_course` | 课程 | trainer |
| `biz_trainer` | 师资 | 被课表引用 |
| `biz_class` | 培训班次 | plan/dept |
| `biz_class_student` | 班级学员(含本班累计学时) | class/user |
| `biz_class_schedule` | 课表节次 | class/course/trainer |
| `biz_attendance` | 节次签到 | schedule/user |
| `biz_hour_record` | 学时台账(唯一统计口径) | user/class/schedule/course |
| `biz_eval_template` | 评估模板(条目JSON) | — |
| `biz_eval_record` | 评估作答(作答JSON) | template/class/user |

主键统一自增,业务表带 `del_flag` 逻辑删除与 `create_time/update_time` 审计字段;数据字典(类别、状态等)以常量+代码表注释方式固化,保证口径一致。

## 6. 权限模型

```
sys_user ──< sys_user_role >── sys_role ──< sys_role_menu >── sys_menu(M目录/C菜单/F按钮)
                                                     └── perms 权限标识(如 biz:need:audit)
```

- 登录签发 JWT(24h);拦截器解析后加载角色与权限集合写入线程上下文;
- 接口层:`@RequirePerm("biz:need:audit")` 双重校验,`admin` 角色放行全部;
- 前端:菜单树动态渲染侧边栏,`v-perm` 指令控制按钮可见性;越权请求由后端拒绝并提示;
- 员工自助接口(申报、报名、评估填写、我的学时)仅要求登录,数据范围在服务层按登录人收敛。

## 7. 关键业务规则(可配置项)

| 参数键 | 默认值 | 说明 |
| --- | --- | --- |
| `hour.required.manager` | 110 | 管理干部年度学时要求 |
| `hour.required.professional` | 90 | 专业技术人员年度学时要求 |
| `hour.required.staff` | 90 | 一般员工年度学时要求 |
| `hour.factor.late` | 0.5 | 迟到按节学时的折算系数 |

## 8. 非功能设计与扩展点

- **安全**:BCrypt 密码存储、JWT 过期失效、越权拦截、SQL 全部参数化;生产须更换 JWT 密钥;
- **审计**:操作日志含参数快照与失败原因;
- **性能**:分页插件统一分页;统计 SQL 走聚合索引;后续可引入 Redis 缓存权限与热点统计;
- **扩展点**:
  - 统一身份认证(SSO/CAS、企业微信/钉钉扫码);
  - 课件附件对象存储、在线考试与题库、结业证书生成;
  - 讲师课酬结算、经费执行跟踪;
  - 消息通知(开班提醒、评估催办、达标预警);
  - 移动端(H5/小程序)签到与学习;
  - 与人力资源系统对接人员和组织数据。
